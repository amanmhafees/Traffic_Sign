TRAFFIC SIGN RECOGNITION – AUGMENTATION ISSUES AND FIXES
======================================================

PROJECT CONTEXT
---------------
The YOLO-based traffic sign recognition model correctly detects traffic signs
but frequently predicts the wrong class (mostly "gap in median").
Bounding boxes are manually annotated and correct.

ROOT CAUSE
----------
The issue is NOT feature extraction or YOLO architecture.
The primary problem is aggressive and unrealistic data augmentation that
destroys class-discriminative features of traffic signs.

------------------------------------------------------
PROBLEMS IDENTIFIED
------------------------------------------------------

1. Unrealistic Rotation
-----------------------
RandomRotate90 and large rotation angles (±15°, ±30°) were used.
Traffic signs are never rotated by 90° in real-world scenarios.
Orientation is a class-defining feature.

Impact:
- Model learns non-existent sign appearances
- Confuses symbol orientation across classes

2. Color Semantics Destroyed
----------------------------
HueSaturationValue with large limits was applied.
Traffic sign colors (red, blue, yellow) are legally standardized.

Impact:
- Model loses ability to distinguish mandatory, cautionary, and prohibition signs
- Severe class confusion occurs

3. Shape Distortion
-------------------
GridDistortion and Perspective transforms were applied.
Traffic signs are rigid, flat, and geometrically consistent.

Impact:
- Symbol geometry is corrupted
- Model learns incorrect shape priors

4. Weather Augmentations Cause Background Bias
----------------------------------------------
RandomRain, Fog, Shadow, and SunFlare were used.
These affect background more than the sign itself.

Impact:
- Model associates road texture and environment with certain classes
- Bias towards background-heavy classes like "gap in median"

5. Bounding Box Integrity Risk
------------------------------
Albumentations can drop or shrink bounding boxes after augmentation.
The code does not validate bbox count or size after transformation.

Impact:
- Bbox–class mismatch
- Partial or tiny signs labeled as full objects
- Confident but wrong predictions

6. Over-Aggressive Oversampling
-------------------------------
Classes were force-augmented to 300 images regardless of original count.

Impact:
- Synthetic data dominates real data
- Model overfits to augmented artifacts

------------------------------------------------------
WHAT NEEDS TO BE DONE (FIXES)
------------------------------------------------------

1. Restrict Augmentations to SAFE Transformations
-------------------------------------------------
Allowed:
- Rotation limited to ±5 degrees
- Small brightness and contrast changes
- Mild Gaussian noise
- Light blur (blur_limit ≤ 3)

Remove Completely:
- RandomRotate90
- HueSaturationValue
- Perspective / GridDistortion
- Weather effects
- ChannelShuffle
- Grayscale conversion

2. Enforce Bounding Box Validation
----------------------------------
Before saving augmented images:
- Ensure number of bboxes == number of class labels
- Reject bboxes with width or height < 5% of image
- Reject partially visible or clipped signs

3. Limit Augmentation Quantity
------------------------------
- Do NOT force all classes to equal size
- Maximum augmentation should be 1.5x original data
- Prefer real data over synthetic data

4. Preserve Traffic Sign Semantics
----------------------------------
Augmentation must NOT:
- Change sign color meaning
- Alter symbol geometry
- Modify orientation beyond realistic limits

------------------------------------------------------
EXPECTED RESULT AFTER FIXES
------------------------------------------------------

- Significant reduction in wrong class predictions
- Less bias toward "gap in median"
- Improved per-class precision
- More stable and meaningful training convergence
- Model learns sign symbols instead of background context

------------------------------------------------------
FINAL NOTE
------------------------------------------------------
Feature extraction is already handled by YOLO.
Improving data quality and realistic augmentation is the correct solution.
